PART 1 — WHAT HAS BEEN BUILT
====================================================================

A. The framework (original Phases 1-14)
   Drift events in -> analysis (KS/PSI, reuse or adapt) -> decision (rules, optional LLM)
   -> adaptation (sklearn, XGBoost, PyTorch; fine-tune or retrain; sandboxed generated
   code) -> validation -> registry, with idempotent events, model locks, retries,
   content-hashed data versions and lineage, role-based API keys, audit trail,
   Prometheus metrics, CDC, and the oran-adapt CLI.

B. Production hardening (Hardening Phases 1-15), answering the ten integration findings
   1  Model registry port: mlflow, filesystem, mirror, sagemaker, vertex
   2  Deployment port with read-back: KServe, Seldon, k8s, Triton, BentoML, SageMaker,
      Vertex, GitOps, webhook
   3  Outbound notifications through a durable outbox (webhook, Slack, PagerDuty, email,
      Kafka, SQS, SNS, Pub/Sub, NATS)
   4  Data by reference (file, http, fsspec, s3, gcs; and since PR #5 sql and rankpi),
      CDC from any table
   5  Jobs leave the API: durable queue, leases, deadlines, cancel; database, celery, rq,
      kubernetes
   6  Statistical validation gate with guardrails; shadow, canary, A/B and manual delivery
      with automatic rollback
   7  Packaging: api/worker/migrator images, Helm chart, kustomize, expand-only migrations
   8  LLM optional and off by default; rules-only path; self-hosted provider option
   9  Identity: OIDC, gateway, mTLS, OPA policy, Vault secrets, SSRF/TLS policy, rate limits
   10 Model-type plugins: tabular, sequence (RNN/LSTM/GRU/TCN/transformer), forecasters, ONNX
   Plus: observability (traces, metrics, dashboards, runbooks), conformance suites per
   port, mutation testing, declarative drift mappers, config lint, ADRs, final audit.
   Mapping of each finding to its code: docs/integration/rankpi.md section 6.

C. rankpi integration (PR #5, merged 2026-10-14)
   - sql dataset adapter: data by database query from any SQLAlchemy database; one
     allow-listed relation per reference, bound filters, read-only and time-limited on
     PostgreSQL, streamed as CSV with a SHA-256 fingerprint.
   - rankpi dataset adapter: the same, plus the schema reference's rules: bounded by
     run_id or `to`; closed runs only; v_run_summary.dropped = 0; cumulative counters
     and dead fields refused; derived views only by default.
   - rankpi rollout metrics adapter: per-arm score, inference_ms, score_term.<name>,
     clipped, delivery_failed and model_metric samples from the ML lifecycle store.
   - config/examples/rankpi.toml (shadow first), config/policies/delivery-rankpi.toml
     (also gates the starvation and fairness terms), docs/integration/rankpi.md.

D. Bugs found and fixed while getting CI green (PR #5; main's CI was red before)
   - MLflow: every HTTP call to a tracking server failed (MLflow 3.16 rejected the
     backoff value "0.0"), so the compose API never became ready.
   - Worker: an empty WORKER_METRICS_ADDR crashed it at start-up (compose and Helm).
   - Kafka CDC: a missing consumer group aborted the process; a dead broker read as
     "no changes"; a topic not yet created caused a restart loop.
   - werkzeug 3.1.9 (CVE-2026-102598); bandit findings reviewed and annotated.
   - CI: jsonschema was never installed (no unit test ran); build-images spent 43
     minutes exporting image filesystems (now about 6 minutes); compose smoke and
     testcontainers tests corrected.

PART 3 — STILL OPEN (needs a site, credentials or a decision)
====================================================================

      a run_id column and that the views have a ts column (docs/integration/rankpi.md

      BentoML, Argo CD/Flux, real OIDC/Vault/mTLS and the LLM providers are tested only
      against emulators and doubles. Their live tests skip without credentials.

      laptop has neither).

      O-RAN interface (RIC, xApp/rApp, A1/E2/O1). Drift arrives through the HTTP API or
      a mapper.
   Details: docs/LIMITATIONS.md and docs/PRODUCTION-READINESS.md.
